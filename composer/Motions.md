# Motions browser

Open **Performances** in Crest’s bottom strip. It starts at **Expressions → Performances → All subgroups**, showing all 233 performances in the installed Scaler 3.4.0 bank. Select one of the 13 subgroups to narrow the list. Search matches names, groups, families and linked tags *within the current selection*. Choose **All → All families → All subgroups** to search the entire motion library.

All four columns stay visible and scroll independently. Click a performance to audition it against the sketch, then click **Apply to Sketch 1** (or the named destination row) to assign it. A double-click also assigns. Reopen from that row to see its current choice, or select **Block chords** to clear it. Drag the name or note roll directly to a MIDI track for the **original source MIDI**. The heart toggles a local favourite without applying or auditioning the motion.

**Common progressions** opens a separate pattern/variant comparison. For example, selecting `i-VI-III-VII` shows the seven installed variants together. The labels and small diagrams show each variant's *reference* chords and actual pitches. Chord slots have equal display widths, not recorded note durations. The sketch callback transposes the chosen variant to the composition key.

## Evidence and coverage

- [Image 7 observations](../docs/scaler-workflow.md) and the installed **Scaler 3 User Guide**, PDF pp. 75–76: categories, expression and articulation families, heart, search, graph and title interactions. Crest uses single-click audition and explicit apply so the user can compare gestures without overwriting a sketch.
- [Versioned installation evidence](../docs/scaler-installation.md): 1,335 UUID MIDI files across the two installed builds. Each motion thumbnail decodes the corresponding SMF's note-on → matching channel/pitch note-off gates, with X measured against the source's full cycle. No random or name-derived graphics. Only Passages has stored MIDI among the six documented articulations. The other five branches explain why no source clip is available; Crest doesn't silently substitute an expression MIDI for native generated output.
- **Optional real tag index:** after `python3 composer/tools/index_scaler.py`, run `python3 composer/tools/index_motion_tags.py`, then reopen the editor. Both accept `--output /path/to/local/bank`. The second script verifies the Scaler 3.4.0 executable and table before generating `motion-tags.json` alongside the existing index. No factory tag data is checked in. The plugin reads this sidecar on opening the browser for the first time. Without it all source motions remain available.
- Shipped `tagging_json`: 1,969 rows, whole-file byte range `[41848288,42675871)`, SHA-256 `aa50cb889073f40a36b5c414b742ed77310834e555a651c197a0d4240da90316`. The table contains no UUID. Join the eight identified motion `Type` strings to ZIP families, then require a single matching display `Name` on **both** sides after case-folding, trimming/collapsing whitespace and `colour` → `color`. Split comma-separated `Feel/Mood` and `Genre` values. No fuzzy matching, variant inheritance, or S2-only attributions. This produces **754 linked motions**, **42 moods**, **17 genres**; **581** union motions remain available in **No linked tag**. These are conservative joins of actual tags, not a recovered Scaler runtime query algorithm.
- Favourites are persisted by MIDI UUID in `motion-favourites.txt` in the Crest bank directory. They are independent of Scaler's favourites.

## Integration and verification

`BankBrowser(const LocalBank&)`, `onMotion`, `onProgression` and `onClose` retain their existing contracts. Call `showMotions()` or `showProgressions()` before making the component visible. Each route resets search and establishes a useful default. Callbacks receive the *bank record*, not a title lookup; the boolean is `true` for preview, `false` for application.

Native GUI automation can use component IDs `bank.search`, `bank.categories`, `bank.families`, `bank.groups`, `bank.items`, and (on the progressions page) `bank.patterns`. Use `ListBox::getListBoxModel()->getNameForRow(row)` to inspect exact row names and `selectRow(row)` to navigate; the result's native button `bank.heart` toggles that specific motion. Button labels are **Audition**, **Use in sketch**, **Close**. `motion::Roll::read(file).noteCount()` counts the literal pairs used by the preview.
